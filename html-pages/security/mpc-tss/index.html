Secret Sharing · MPC · Threshold Signatures

把私钥切成碎片，
还是让它永远不完整？

“私钥分割”听起来像把一把钥匙锯成几段，拼起来就能用。 但在密码学里，真正有价值的是：任何一方都不需要看到完整私钥，也能完成签名。 这篇从 Shamir 的多项式开始，走到 TSS 的阈值签名与 DKG。

玩一下 Shamir 看 TSS 怎么签
t-of-n 阈值 Shamir / Lagrange FROST / GG20 / CMP

01 · Three Different Things

秘密分享、MPC、TSS 不是同义词

它们经常一起出现，但解决的问题不同：一个解决“秘密怎么存”，一个解决“多方怎么算”， 一个解决“签名怎么在不拼出私钥的情况下完成”。

Secret Sharing

存

把秘密 s 拆成 n 份；任意 t 份可以恢复 s，少于 t 份得不到信息。

  • Shamir：多项式插值
  • Additive：全部相加才恢复
  • 输出是“份额”，不是签名

MPC

算

多方在不暴露各自输入的前提下，共同计算一个函数。

  • 秘密分享是常用工具
  • 还有混淆电路、OT 等路线
  • 关心恶意模型、诚实多数

TSS

签

t-of-n 参与方共同产生一个标准签名；私钥从未被重建。

  • 通常 = SSS/DKG + MPC 签名
  • 输出是普通 ECDSA/Schnorr 签名
  • 验证者看不出它是阈值签的

02 · Why Naive Splitting Fails

“把私钥切两半”为什么不够

直接拼接、XOR 分享、Shamir 分享，看起来都是“分开存”，安全性质却完全不同。

直接拼接

私钥 = A1B2C3，share1 = A1，share2 = B2C3。

拿到任意一份，就泄露了私钥的一部分；没有阈值，必须全部拼起来。

XOR / 加法分享

share1 随机，share2 = secret XOR share1。

单份看起来均匀，但必须全部份额才能恢复；丢一份就永久丢失，且没有 t-of-n。

Shamir 分享

用 t-1 次多项式把 secret 藏在 f(0)。

任意 t 份可恢复；少于 t 份信息论上什么都得不到；有冗余，可容忍部分份额丢失。
!

最重要的一句话： 秘密分享只解决“怎么存”。如果你把 t 份份额恢复成完整私钥再签名， 你只是把单点故障从“一台机器”变成了“一次签名过程”。TSS 的价值在于签名时也不重建私钥。

03 · Shamir SSS

一条多项式，藏一个秘密

Shamir 的核心不是“随机切片”，而是“用 t-1 次多项式把 secret 放在 f(0)”。 任意 t 个点唯一确定多项式；少于 t 个点则有无穷多条可能曲线。

构造

  1. 选一个素数 p，秘密 s ∈ F_p。
  2. 随机选 a₁…a_{t-1}，令 f(x)=s+a₁x+…+a_{t-1}x^{t-1}。
  3. 对 i=1…n，份额是 (i, f(i) mod p)。
  4. 任意 t 份用 Lagrange 插值算 f(0)，就是 s。

为什么 t-1 份不够

对任意一个候选秘密 s'，都存在一条 t-1 次多项式同时穿过已揭示的 t-1 个点和 (0,s')。 所以这 t-1 个点不能排除任何 s'；这就是信息论安全。

s = Σ y_i · L_i(0) mod p L_i(0) = Π_{j≠i} x_j / (x_j − x_i) mod p

04 · Threshold SIG

签名时，私钥不在场

TSS 把“份额”带进签名协议：每个参与方用自己的份额计算 partial signature， 最后由组合者合成一个标准签名。没有人需要把 x 拼出来。

P1 份额 x₁

持有 (x₁, k₁)

x₁, k₁

P2 份额 x₂

持有 (x₂, k₂)

x₂, k₂

P3 份额 x₃

持有 (x₃, k₃)

x₃, k₃
1
DKG / 份额

每个参与方持有 xᵢ；公钥 Y = g^x，但没有人知道 x。

2
Nonce 承诺

各方选 kᵢ，发布 Rᵢ = g^{kᵢ}；聚合 R = Σ Rᵢ。

3
挑战

c = H(R, m)，把消息和 nonce 绑定。

4
Partial signature

sᵢ = kᵢ + c·xᵢ；只需一个 quorum（例如 P1、P3）。

5
合成与验证

s = λ₁s₁ + λ₃s₃；验证 g^s = R·Y^c。

1 / 5
DKG：份额分配完成。公钥 Y 可以公开，私钥 x 不在任何单台机器上。
combiner: 等待 quorum…
!

上面是简化 Schnorr： s = k + c·x 是线性的，所以 partial signature 可以直接相加。 真实 FROST 还要处理 nonce 承诺、binding factor、恶意参与方和 identifiable abort； ECDSA 更麻烦，因为 s = k⁻¹(H(m)+r·x) 里有模逆，需要 Paillier/MtA/OT 等协议（GG18/GG20/CMP）。

05 · DKG & Refresh

不要把所有信任交给一个 dealer

最朴素的 Shamir 需要一个 dealer 知道完整秘密并分发份额；这又制造了一个单点。 DKG 让每个参与方共同生成份额，没有人知道完整私钥。

Dealer-based

  • dealer 生成 f(x)，分发 (i, f(i))。
  • dealer 知道 secret；必须被信任或立即销毁。
  • 适合离线备份、恢复场景。

Joint DKG

  • 每个参与方贡献一个多项式 fᵢ(x)。
  • 最终份额是 f(x)=Σ fᵢ(x)，公钥是承诺的聚合。
  • 用 Feldman/Pedersen VSS 校验份额；恶意行为可投诉/中止。
Feldman VSS: C_j = g^{a_j} mod p // 对系数做承诺 share_i = f(i) mod q 验证: g^{share_i} = Π_j C_j^{i^j} mod p Refresh: 保持 Y = g^x 不变，重新分享 x 旧份额立即作废，降低长期泄露风险
✓

Proactive security： 定期 refresh 份额，但不改变公钥。攻击者必须在一个刷新周期内同时拿到足够多的份额， 而不是“慢慢攒几年”。

06 · Security Boundaries

最容易踩的坑

密码学协议正确，不代表部署安全。TSS 的失败模式往往在协议之外：份额、网络、随机数、运维。

恢复即失败

如果签名前把 t 份份额恢复成完整私钥，单点故障又回来了；SSS 只适合备份/恢复，不适合在线签名。

Dealer 信任

dealer 知道 secret；没有 VSS/DKG 时，dealer 可以给不同参与方不一致的份额。

Nonce 复用

ECDSA/Schnorr 的 nonce 一旦复用，私钥可能被直接解出；阈值协议同样受此约束。

恶意参与方

半诚实模型不够；生产要考虑恶意模型、identifiable abort、投诉与重试。

网络与重放

会话 ID、消息认证、重放保护、超时/中止；不要把“重试”做成 nonce 重用。

份额存储

份额也是私钥材料；HSM、隔离域、访问审计、备份加密，一个都不能少。

阈值 ≠ 多签

TSS 输出单个公钥/签名，链上看起来像单签；多签有独立公钥和链上策略，问责更直接。

实现成熟度

协议论文正确不等于实现正确；侧信道、序列化、错误处理、依赖版本都要审计。

07 · Math Appendix

把公式放在一起

不需要背，但要知道每个符号在协议里对应什么；尤其是 Lagrange 系数和非ce 的位置。

Shamir / Lagrange

f(x) = s + a₁x + … + a_{t-1}x^{t-1} mod p share_i = (i, f(i)) s = f(0) = Σ_{i∈Q} y_i · L_i(0) L_i(0) = Π_{j∈Q, j≠i} x_j / (x_j − x_i)

Threshold Schnorr（简化）

x = Σ λ_i x_i, k = Σ λ_i k_i Y = g^x, R = g^k c = H(R, m) s_i = k_i + c·x_i s = Σ λ_i s_i = k + c·x verify: g^s = R · Y^c

ECDSA 为什么更难

s = k⁻¹ · (H(m) + r·x) mod n r = (g^k).x mod n k⁻¹ 和 r 都把 nonce 与私钥 耦合在一起；分布式计算模逆 需要额外协议（Paillier/MtA/OT）。

Feldman VSS

C_j = g^{a_j} mod p share_i = f(i) mod q verify: g^{share_i} = Π_j C_j^{i^j} mod p 承诺让参与方在不暴露份额的 前提下验证 dealer 的一致性。
∑

符号边界： 上面的公式是教学简化。真实协议还要处理群阶、哈希到标量、nonce 承诺、binding factor、 零知识证明、消息序列化和 abort 语义；不要直接拿这些公式实现生产协议。

最小检查清单

  • 威胁模型：诚实多数还是恶意多数？谁可能串谋？需要 identifiable abort 吗？
  • Dealer vs DKG：是否有一个知道完整秘密的 dealer？能否接受这个单点？
  • VSS：份额是否可验证？dealer/参与方发错份额时能否投诉？
  • Nonce 纪律：每次签名 fresh nonce；重试、超时、并发都不能复用。
  • 份额存储：HSM/隔离域/加密备份；不要把 t 份放在同一台机器。
  • Refresh：定期重新分享，保持公钥不变，降低长期泄露风险。
  • 协议审计：实现版本、依赖、序列化、错误处理、侧信道都要审。
  • 恢复演练：t-of-n 恢复、份额丢失、参与方离线、灾难切换都要实际演练。
