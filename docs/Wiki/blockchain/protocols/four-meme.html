four.meme：BSC 上的 bonding curve 发射台

一句话： four.meme 把“发币 + 初始定价 + 毕业后上 PancakeSwap”打包成一条流水线：创建者在内部曲线池里被买卖，进度到 100% 后把剩余代币和募集的报价资产迁到 PancakeSwap 建池。

这篇的重点不是判断某个 meme 会不会涨，而是回答：谁在定价、资金在哪个合约里、毕业后流动性由谁控制、哪些环节只能信平台。

1. 角色与资产流​

角色做什么拿到什么
创建者部署 token、可选在同一笔交易里先买一部分token 份额；毕业后可能获得 LP 相关权益（以平台规则为准）
交易者用 BNB/USDT 等报价资产在内部曲线买入，或卖出 tokentoken 或报价资产，扣除交易费
曲线池持有报价资产与 token，按曲线报价不托管用户私钥；由平台合约管理
平台提供前端、曲线参数、毕业与迁移逻辑、费用接收方交易费与可能的迁移费用
PancakeSwap毕业后承接流动性外部 AMM 池，独立于 four.meme 曲线

典型资产流：

报价资产 ──buy──> 曲线池 ──> 用户得到 token
token ────sell──> 曲线池 ──> 用户得到报价资产（扣费）
进度 100% ──migrate──> 剩余 token + 募集报价资产 ──> PancakeSwap 池

关键点：毕业前，价格由内部曲线决定；毕业后，价格由 PancakeSwap 池和外部市场决定。 这是两个完全不同的定价场所，不能把毕业前的“进度”当成毕业后的流动性深度。

2. 核心状态​

状态存在哪里关键字段/含义
TokenBEP-20 合约总量、税率（若为 tax token）、权限、黑名单/暂停等
曲线池平台合约报价资产余额、token 余额、虚拟储备、当前进度、毕业阈值
费用平台/费用接收方交易费率、最低费用、推荐返佣（以平台规则为准）
毕业状态平台合约/事件是否已毕业、迁移交易、Pancake pair 地址
外部流动性PancakeSwap Pair两种资产储备、LP 总量、LP 持有者

读数据时不要只看 token 价格：至少同时确认 曲线池地址、报价资产、进度、毕业事件和 Pancake pair。

3. 关键机制​

3.1 内部曲线：用虚拟储备定价​

这类发射台通常维护一条“虚拟储备”曲线：池子里实际只有部分token/报价资产，但报价按虚拟储备计算，从而让初始价格很低、随着买入逐步上升。具体公式、初始虚拟储备和毕业阈值由平台合约决定，不同版本/不同报价资产可能不同。

因此：

  • “进度 80%”只表示曲线参数下的某个位置，不直接等于“还有 20% 的币可买”。
  • 大额买入的滑点由曲线形状决定，不能套用 Uniswap 的 x*y=k 储备去算。
  • 卖出是否可执行、是否有冷却/限制，要看平台当时规则。

3.2 1% 交易费与费用去向​

four.meme 文档写明交易费约为 1%（最低费用另有规定），创建本身只收链上 gas。费用在买入/卖出时扣除，具体分配（平台、推荐人、LP/回购等）以合约和文档为准。

对分析者的含义：同样的曲线，费率不同，往返成本就不同。 一次买入再卖出，除了价格滑点，还要承担两次费用和 BSC gas。

3.3 毕业迁移：从曲线到 PancakeSwap​

文档描述：当内部池达到 100%，20% 的 token 和募集到的全部报价资产会配对进入 PancakeSwap 建立流动性。这里需要核对的是：

  1. 迁移是自动触发还是需要人调用？
  2. 迁移后 LP token 由谁持有、是否锁定/销毁？
  3. 剩余 80% token 如何处理（销毁、锁仓、归创建者）？
  4. 毕业失败/拥堵时，曲线是否还能交易？

这些问题决定了“毕业后抛压”和“流动性是否可撤”的答案。不要假设毕业 = 流动性永久锁定。

3.4 多报价资产与 tax token​

平台支持用 BNB、USDT 等作为交易对，也允许带转账税的 token。对分析的影响：

  • 报价资产不同，资金流和计价就不同，不能把 BNB 池的进度套到 USDT 池。
  • tax token 在买入/卖出/转账时可能额外扣税，实际到手数量与曲线报价不一致。
  • 个别 token 可能有黑名单、暂停、增发、权限后门；这些是 token 层风险，不是曲线层风险。

5. 失败模式​

失败触发方式观察点
曲线参数不透明平台调整虚拟储备/毕业阈值合约参数、历史进度曲线、官方公告
毕业后流动性可撤LP 未锁定或由平台/创建者控制Pancake pair 的 LP 持有者、锁仓合约
迁移失败/延迟毕业交易失败、拥堵、合约暂停毕业事件、曲线状态、池子是否还能卖
Tax/honeypottoken 合约在转账时收税、限制卖出模拟买卖、token 权限、黑名单
狙击与 dev buy创建者同交易先买、机器人抢开盘首笔交易、持仓分布、区块内交易
前端/API 依赖官网或接口不可用、报价错误直接读链上合约 vs 前端报价
假币/仿盘同名 token、非官方合约合约地址、部署者、官方白名单
MEV买卖被夹、滑点被吃交易排序、私有交易、滑点设置

6. 读数据与检查清单​

  • 先确认 token 合约地址和报价资产，不要用名称/符号定位。
  • 找到当前曲线池合约，读进度、虚拟储备、毕业阈值和费用。
  • 核对创建者首笔买入、持仓集中度和是否有 tax/黑名单权限。
  • 用小额买卖模拟实际到手数量，比较曲线报价与真实余额变化。
  • 查毕业事件和 Pancake pair，确认迁移是否完成、LP 由谁持有。
  • 检查平台是否有暂停/升级/费用修改权限，以及这些权限的地址。
  • 把“毕业前曲线风险”和“毕业后 AMM 风险”分开评估。
