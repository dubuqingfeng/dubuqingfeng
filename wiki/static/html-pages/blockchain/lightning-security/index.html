LND v0.21.8-beta · Source Walkthrough

旧状态广播后，
谁在什么时间拿走钱？

Lightning 的安全不是“链下更快”，而是 链下快速达成状态，链上保留可强制执行的合同。 对方广播已撤销的承诺交易时，决定结果的是三件事： 你还记不记得那个状态、还掌不掌握它的 secret、以及你是否在对方花掉输出前把 justice tx 发出去。

02 · Two Commitments

同一状态，为什么有两笔交易？

承诺交易是非对称的。谁广播，决定了谁的输出带 CSV、谁可以直接花； 也决定了哪一侧带撤销分支。

Alice 持有的本地 commitment Bob 眼中的 Alice commitment 广播方

同一笔状态，Alice 的 to_local 带 CSV 和撤销分支。

  • Alice 的 to_localCSV 延迟 + 撤销分支CSV 延迟
  • Bob 的 to_remote直接支付
  • HTLC 输出按第二层脚本
  • commit fee由 Alice 承担

Alice 眼中的 Bob commitment Bob 持有的本地 commitment 被广播方

Bob 的 to_local 带它自己的 CSV；Alice 的输出通常是 to_remote。

  • Bob 的 to_localCSV 延迟 + 撤销分支
  • Alice 的 to_remote直接支付
  • HTLC 输出按第二层脚本
  • commit fee由 Alice 承担
✓

撤销密钥不是“另一个公钥”： R = revoke_base · H(revoke_base‖commit_point)， C = commit_point · H(commit_point‖revoke_base)， revocation_pubkey = R + C。 要花撤销分支，必须同时有撤销基点私钥和该状态的 commitment secret。

04 · Static Channel Backup

SCB 恢复后，为什么不能主动退出？

SCB 是“频道外壳”，不是频道状态。它包含 key locator 和 shachain 根， 但不含当前 commitment tx 和 revocation log。

1 恢复外壳

容量、funding outpoint、本地 key locator、远端公钥、shachain 根。

2 连接 peer

用 SCB 里的地址连接；对方必须在线，才可能触发后续流程。

3 DLP

ErrCommitSyncLocalDataLoss 携带对方的 commit point；MarkDataLoss，不 force close。

4 只取回主输出

对方 force close 后扫本地输出；空 commitment，HTLC 不恢复。

SCB 能做什么

  • 识别频道、连接 peer
  • 从种子重新派生本地密钥
  • 恢复 shachain 根
  • 在对方 force close 后取回本地主输出

SCB 不能做什么

  • 主动 force close（没有当前 commitment tx）
  • 惩罚对方广播的旧状态（没有 revocation log）
  • 恢复 HTLC 或在途支付
  • 保证你能退出（对方必须 force close）
!

“我有 SCB，所以安全”是危险的。 v0.21.8 的 rpcserver.go 明确拒绝对 ChanStatusRestored / ChanStatusLocalDataLoss 的 coop/force close；恢复后的频道只能等对方关闭。
